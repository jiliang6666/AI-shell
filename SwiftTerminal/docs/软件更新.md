# 软件更新

栈桥使用 Sparkle 2 的 EdDSA 更新签名。在“设置 → 更新”可以手动检查或开启定期检查；更新包先验证签名，再由 Sparkle 下载并提示安装。代码和 Release 共用公开仓库 `jiliang6666/AI-shell`，Feed 为其 GitHub Releases 中的 `appcast.xml`。

当前打包默认使用版本 `1.0.0`、build/revision `100`。首个含 Sparkle 的版本需要手动安装一次；以后只有当仓库 Release 包含签名 `appcast.xml` 和更新 ZIP 时，应用内检查才会发现更新。本地不会自动上传、推送或创建 Release。

更新发布不需要 GitHub token。打包时使用公开仓库和 EdDSA 公钥：

```sh
ZHANQIAO_UPDATE_REPOSITORY=jiliang6666/AI-shell \
ZHANQIAO_APP_VERSION=1.0.0 \
ZHANQIAO_APP_BUILD=100 \
ZHANQIAO_UPDATE_REVISION=100 \
./scripts/package-app.sh
```

包内公钥默认取栈桥专属 Sparkle Keychain 账户 `com.zhanqiao.sparkle`。对应 EdDSA 私钥只保存在本机钥匙串，通过 `generate_appcast` 访问；不要把私钥导出到仓库。更新密钥创建后请使用钥匙串自身的备份方式保管。

首个启用 Sparkle 的安装包需手动安装一次。它的 `.app` 需要先归档成完整 ZIP，再生成签名 appcast：

```sh
mkdir -p build/update-assets
ditto -c -k --sequesterRsrc --keepParent build/栈桥.app build/update-assets/栈桥-1.0.0.zip
ZHANQIAO_UPDATE_REPOSITORY=jiliang6666/AI-shell \
ZHANQIAO_APP_VERSION=1.0.0 \
ZHANQIAO_UPDATE_REVISION=100 \
./scripts/generate-update-appcast.sh
```

首个更新启用版本的 ZIP 与 `appcast.xml` 需由仓库所有者作为资产上传到 `v1.0.0` Release。之后每次更新都要递增 `CFBundleVersion`、`CFBundleShortVersionString` 和 `ZhanqiaoUpdateRevision`；至少确保内部 revision 严格大于已发布的 revision。打包脚本通过 `ZHANQIAO_APP_VERSION`、`ZHANQIAO_APP_BUILD` 和 `ZHANQIAO_UPDATE_REVISION` 设置这些值。公钥更换会导致已安装的旧版无法验证新密钥，换钥需另行发布需要手动安装的迁移版本。

`generate-update-appcast.sh` 只在本地生成、签名 appcast 和更新资源，不上传 GitHub、不创建 Release。发布过程仍由仓库所有者执行。
